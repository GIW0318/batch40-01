# GSB Bugfix Task
## 题面
流量审计平台的日报这周被财务打回来了，说和交换机计数器差出一大截，运营商账单也对不上。我先把采集链路从头到尾看了一遍。正向和反向流各记了一条，同样的字节被算了两遍；五元组里源端口方向处理错，客户端重连后旧流和新流并成一条；32 位字节计数回绕，一次回绕被记成几十 G 的尖峰；活跃超时和空闲超时用同一个值，长连接被切成很多段，段数虚高；采样率在采集和聚合各乘了一次，总量放大一百倍；导出记录乱序到达，旧计数把新计数覆盖回去；看到 FIN 或 RST 不关流，连接结束后计数还在涨；ICMP 的类型和代码没进键，不可达和超时被合并；IPv6 的流标签没参与区分，不同业务算到一起；五分钟聚合桶按处理时刻对齐，同一分钟的数据落进两个桶；Top N 重流量的估算误差没有标注，运营当成精确值用；重复导出的同一条记录被加了两次。netflow_aggregator.py 的 FlowRollup 要先把五元组按通信方向归一，正向和反向合成一条会话；字节和包计数要处理回绕，按差值累加；活跃超时和空闲超时分开配置并真正生效；采样率只应用一次；导出记录按序列号和时间排序，旧记录不能覆盖新记录；TCP 的 FIN 和 RST 要关闭流；ICMP 类型代码、IPv6 流标签参与聚合键；时间桶按固定边界对齐；Top N 要给误差范围；exporter 加序列号去重；过期数据按保留策略清理。模块自带的十五项检查现在全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
