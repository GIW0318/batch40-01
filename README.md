# GSB Bugfix Task
## 题面
多租户动态口令服务上线后，不同客户的时间漂移开始互相打架：漂移窗口是全局写死的，认证器慢十秒的租户永远验不过，快的那家窗口又宽得能蒙；时间步按服务器本地时区取整，夏令时切换当天整个租户的码全部错位；密钥轮换的过渡期只让新密钥生效，旧认证器用户被集体挡在门外，过渡期过了旧密钥反而还能验过；两个租户的密钥前缀相同，输入对方刚用过的码也能进；Base32 密钥大小写、空格和补全等号处理不一致，导入时有的能解有的不能；六位码和八位码混用，前导零被当成没有；失败次数只在进程内记，重启或换一台网关就清零；时间步边界按四舍五入和向下取整两种算法并存，临界那一两秒里正确码时好时坏；同一账号绑了两个认证器时只认最后绑定的那个，解绑后旧密钥仍然有效；审计只记成功不记失败。totp_drift_ledger.py 的 TotpDriftLedger 要按租户和用户分别维护漂移补偿与消费记录，窗口只在各自配置范围内生效，时间步统一按 UTC 取整，密钥轮换要有明确重叠期且新旧都可验，密钥按租户隔离，Base32 输入先归一，六位和八位分开处理，失败计数跨进程共享，多认证器逐个核对，结果给出当前步、补偿量和拒绝原因。仓库里那十五条用例没有一条能过。

```bash
python -m pytest tests -q
```
