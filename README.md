# GSB Bugfix Task
## 题面
海外节点扩容后，一条办公网段被合作方又转卖了一次，流量绕到第三个自治域才回来。复盘时发现边界设备对关系图的理解是错的：它把客户宣告当成了对等宣告，出口策略只比前缀长度，不看对方在路径里的位置；路径向量里夹着集合段，代码把它当普通序列继续算；预挂靠把路径拉长后反而绕过了最短判断；RPKI 结果为非法时只改了本地优先级；ASPA 关系缺失时直接按可信处理；两个地址族共用一套长度上限；联盟内的子自治域没有展开；BGP 会话重置后旧的宣告没有撤销；社区标签能覆盖出口策略；本地优先级高的泄漏路由压过正常路径；路由抖动时抑制器按邻居而不是按前缀计数；导入和导出用了两份不同的前缀集合。bgp_aspath_leak_fence.py 的 AsPathLeakFence 负责 validate、import_policy、export_policy、update 和 snapshot。关系图要区分客户、对等、上游；集合段和缺失的 ASPA 关系一律不接收；预挂靠不能绕过最短路径判断；非法 RPKI 直接丢弃；两个地址族分别限制长度；联盟段展开后再比较；会话重置撤销旧宣告；社区标签不能越权；导入导出共用前缀集合；抖动抑制按前缀维度生效。tests/test_bgp_aspath_leak_fence.py 的十五条断言眼下全红，分别针对客户误判、集合段、预挂靠、RPKI、ASPA、前缀长度、联盟、会话重置、社区标签、本地优先级、抖动抑制和策略一致性。

## 运行方式
```bash
python -m pytest tests -q
```
