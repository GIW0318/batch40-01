# GSB Bugfix Task
## 题面
反作弊封禁上线后，申诉量比封禁量还大。客户端时钟被回拨，遥测事件顺序全乱，系统把正常操作判成加速；同一局上传了两份报告，违规计数翻倍，直接越过封禁线；采样丢失的时段被当成异常空白，一批网络差的玩家被误封；证据哈希链在断点续传后接不上，后面所有证据都不可信；封禁阈值按会话累计，玩家重连就清零，工作室反复重连规避；白名单里的主播仍然被封；申诉成功解封了，但证据记录没标记，下次又拿来封；封禁和解封并发，最终状态一会儿封一会儿解；回放哈希和遥测哈希对不上，系统仍然采信遥测；证据保留期到期自动删除，玩家申诉时无据可查；设备指纹重复，同一网吧的玩家被连坐。telemetry_ban_evidence.py 的 TelemetryBanEvidence 负责 ingest、evaluate、ban 和 appeal。以服务器时间为准重排事件；报告按对局和账号幂等；缺失采样要标记为不可判定而不是异常；哈希链断点要能定位到具体分段；阈值按自然日累计并跨重连保留；封禁和解封走同一状态机；证据保留期不短于申诉期。通知和证据统一用 UTC 并标明时区；封禁状态查询返回当前状态和最近一次变更；证据分段缺失时整条链路标记为不完整，不能继续作为封禁依据；解封后保留封禁历史但标记失效。tests/test_telemetry_ban_evidence.py 的十五个用例目前全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
