# GSB Bugfix Task
## 题面
我们给三家客户开了 SAML 单点登录，最近一家安全厂商发来报告，说能拿任意账号登进我们的后台。复现下来问题集中在断言校验：响应里塞两个断言元素，签名验的是第一个，业务读的是第二个，签名等于白做；签名引用里的标识没有和断言自身的标识逐字比对，改一个字符仍然通过；受众限制只做了前缀匹配，把客户域名拼在我们域名前面也能过；回复对应的请求编号不核对，别人发起的登录响应能被塞进我的会话；目标地址和接收方地址干脆没看，断言可以投到另一个服务。时间条件上，生效时间和失效时间的边界一个算开一个算闭，两台机器差三分钟就时而过时而不时；摘要算法还接受 SHA-1；响应签了名但断言没签时，实现直接把断言当可信；同一份断言在有效期内可以重复使用，登出也不会作废。另外，发行方标识没有和元数据里的实体比对，元数据过期了也照用；加密断言的解密密钥不区分接收方。saml_assertion_fence.py 的 SamlAssertionFence 要把整份响应当成不可信输入，先定位唯一断言再验签，引用标识逐字匹配，受众、接收方、目标地址和请求编号全部核对，时间边界统一，弱算法拒绝，断言一次性消费。眼下仓库里的十五条用例全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
