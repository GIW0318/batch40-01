# GSB Bugfix Task
## 题面
无缝循环的战斗音乐一上线，玩家就说循环点有咔哒声，切歌还会卡半秒。环形缓冲写到尾部绕回头部时没留安全距离，新旧样本重叠，循环点爆一下。seek 的时候解码线程还在往旧位置写，播出来前半段是新歌后半段是旧歌。编码器开头的 priming 样本没有丢，循环一次就多出几十毫秒空白，鼓点越听越拖。欠载之后直接补零，耳机里出现一串咔哒。交叉淡化两条不同采样率的流时没有重采样，切换瞬间音调发尖。预取优先级排在音效后面，进战斗切歌时解码来不及，前两秒是静音。设备采样率从四十四点一变到四十八，环形缓冲容量还按旧率算，频繁欠载。切歌时旧流句柄没等解码回调结束就释放，偶尔崩在音频线程。解码线程优先级太低，后台加载资源时音乐断断续续。循环次数用三十二位样本计数，长时间挂机后计数器回绕，循环点错位。内存池按最长曲目分配，每首短歌也占一大块。播放器需要环绕写入有边界保护、seek 与解码互斥、priming 能按编码器延迟裁掉、交叉淡化先统一采样率、切歌的句柄生命周期安全，缓冲和预取也要有明确的预算。这 15 条用例眼下没有一条通过，全红。

## 运行方式
```bash
python -m pytest tests -q
```
