# GSB Bugfix Task
## 题面
客服后台切到通行密钥登录后，安全同学用一台安卓机做了几次实验，结论是现在的校验形同虚设：同一个挑战串在五分钟内能反复提交，换一个标签页也能过；依赖方标识只拿域名后缀比较，evil-example.com 这种也能通过；来源只校验了主机名，http 和 https、带端口和不带端口被当成一回事。更细的问题在断言里：签名计数器从来不比较，把认证器数据复制到另一台机器上照样登录成功；用户存在标志和用户验证标志解析错位，没做指纹验证的断言也被放行；凭据编号用前缀匹配，两个前缀相同的凭据能互相替代；返回的用户句柄没有和凭据归属核对，A 的凭据能登进 B 的账号；算法字段由客户端传，声明 RS256 时拿公钥当 HMAC 密钥验也能过；认证器数据的扩展区被算进签名范围，长度一改就错。挑战只在页面倒计时里过期，服务端不看；允许凭据列表为空时，实现把它当成任意凭据都行。passkey_assertion_gate.py 的 PasskeyAssertionGate 要把注册和断言两条路径分开校验，挑战绑定会话和动作且一次性消费，依赖方标识按完整主机比较，来源要包含协议和端口，签名计数器严格单调，标志位按位解析，凭据编号精确匹配并核对用户归属，算法只接受白名单。仓库里十五条用例现在全部是红的。

## 运行方式
```bash
python -m pytest tests -q
```
