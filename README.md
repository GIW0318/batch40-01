# GSB Bugfix Task
## 题面
供应链扫描接进流水线后，锁文件审计给了一堆假阴性：包名里的下划线和连字符没有归一，同一个包的两个写法被当成两个依赖；依赖源没有固定，同名包从镜像源拉下来也能过；完整性哈希缺失时直接跳过，等于没有校验；锁文件版本和工具版本不匹配也照读；传递依赖按清单文件重新解析，锁文件里的固定版本被忽略；同一个包的两个版本被合并成一个，漏洞范围算错；Git 依赖指向可移动分支，每次构建拿到的提交不同；可选依赖按平台过滤后没有进入审计，实际构建时又被装上；同伴依赖自动安装的包完全不在审计范围；锁文件里混入合并冲突标记，解析器把它们当成合法条目。lockfile_pin_audit.py 的 LockfilePinAudit 要按锁文件重建完整依赖图：包名统一小写并把连字符和下划线归一，来源必须命中允许的注册表，缺少完整性哈希记问题，锁文件版本不支持就拒绝，传递依赖只信锁文件，同名多版本分开保留，Git 依赖必须固定到提交，可选和同伴依赖按目标平台纳入，冲突标记和坏行报错，结果给出依赖总数、未固定项和来源异常。仓库里十五条用例现在一条也过不了。

## 运行方式
```bash
python -m pytest tests -q
```
