# GSB Bugfix Task
## 题面
直播切片换成新的分段编码方案以后，切片边界花屏，音画也开始错位。强制关键帧插在 GOP 中间，每片第一帧还依赖上一片，独立播放直接绿屏。B 帧的显示时间和解码时间写反，播放器解码顺序一乱就卡住。切片长度按帧数算，可变帧率的源每片实际时长都不一样。多个 worker 并行编码时各自选码率，拼接处画质一档一档跳。场景切换检测和切片边界打架，一个边界插了两个关键帧。音频切片没有对齐视频边界，每片开头都缺一小段。编码器 priming 只在第一片扣掉，后面每一片都累积一点偏移，十片之后口型明显对不上。最后一片不足一个 GOP 被丢掉，结尾直接没了。多个 worker 往同一个封装器写，交错顺序错乱，部分播放器读到负偏移。码率控制跨片不重置，后一片继承前一片的欠账，画质突然崩。切片索引的时间基和媒体时间基不是一个，拖进度条总是偏几秒。切片方案得保证边界强制独立、解码和显示时间严格分开、音视频按同一时间基对齐、priming 每片都处理、并行写封装有顺序保证，切片的码率和时长也要稳定。这 15 条用例跑完没有一条绿的，全红。

## 运行方式
```bash
python -m pytest tests -q
```
