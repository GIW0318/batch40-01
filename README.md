# GSB Bugfix Task
## 题面
构建缓存接上远程共享之后，两个分支开始互相串产物：缓存键只算了源码目录的路径，没算分支和依赖锁的摘要，功能分支命中了主干的旧对象；编译参数里的优化级别和目标架构没有进键，换架构构建直接拿到错误二进制；缓存条目没有完整性校验，远程节点返回半截文件也照用；不同项目的缓存目录没有隔离，A 项目能读到 B 项目的构建产物；缓存写入不是原子的，另一个任务读到只写了一半的归档；缓存过期时间按写入时间算，长期不用的热门条目先被清掉；依赖被撤回后缓存仍然命中，漏洞版本继续进入产物；缓存键里的上跳段没有归一，能落到别的命名空间；并发写入同一个键时后写覆盖先写，没有冲突检测；命中统计只记了次数，不记命中的键和来源。artifact_cache_key.py 的 ArtifactCacheKey 要把缓存键和读写流程都收紧：键包含源码摘要、分支、依赖锁摘要、工具链版本、编译参数和目标平台，参数按名称排序；条目带内容摘要并在读取时校验；缓存按项目和租户隔离；写入先落临时文件再原子替换；过期按最后访问时间；依赖撤回要让相关键失效；路径归一后不得逃出命名空间；并发写同一键要检测冲突；统计记录键、来源和命中结果。仓库里十五条用例眼下全部报错。

## 运行方式
```bash
python -m pytest tests -q
```
