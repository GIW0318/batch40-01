# GSB Bugfix Task
## 题面
内网穿透网关改成多路复用以后，大文件传到一半就停住，断线重连后消息还会乱序。接收方消费完数据没有把窗口还回去，发送方传到 64K 就再也发不动；关闭一条流后流号被复用，旧流的迟到帧被当成新流的数据；控制帧插在数据帧中间，解析器把控制帧长度当成数据长度，后面全错位；一端半关闭后整个连接被拆掉，另一方向还没发完的数据直接丢了；保活超时把正在慢速传输但仍有进展的流判死；断线重连后未确认帧从头重放，接收方看到重复和倒序；单帧长度声明超过上限时先分配内存再校验，一个包就能打满内存；单流窗口大于连接窗口，两条流互相等对方释放，直接死锁；高优先级流一直占着发送队列，低优先级流完全饿死；同一个流号重复打开也被接受，两个发送端写同一条流；已经重置的流再收到数据还继续缓存；乱序到达的帧被直接丢掉，而不是按序号缓冲。tunnel_mux_window.py 的 TunnelMuxWindow 要同时维护连接级和流级窗口，消费后及时回窗口更新，流从打开到半关闭到关闭要有完整状态机，控制帧优先处理但不能破坏数据边界，半关闭只关一个方向，保活按是否有进展判断，重连从已确认偏移续传，帧长先校验再分配，窗口不变量要被检查，多条流按权重公平调度，重复打开和重置后数据都要拒绝，乱序帧进缓冲，快照能一致读出连接和所有流的状态。自带的十五条用例现在全是失败。

