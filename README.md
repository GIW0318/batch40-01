# GSB Bugfix Task
## 题面
账号库的密码哈希要从业余配置迁到统一参数，迁移脚本上线后登录事故不断：bcrypt 成本为四的旧哈希被当成合格，永远不升级；Argon2 的内存参数按字符串直接比较，二百五十六和一千零二十四被当成一样；胡椒密钥轮换后只拿新密钥试，老用户全部登录失败，脚本又回退到不加胡椒的路径，等于绕过了胡椒；存储的哈希格式损坏时迁移任务直接抛异常，整批队列卡死；未知用户和密码错误返回耗时差了一个数量级，能被用来枚举账号；同一个用户并发登录触发两次重哈希，后写的把先写的覆盖回旧参数；升级队列没有去重，一个热门账号排了几百条任务；迁移时新盐复用同一批随机源，多个用户哈希前缀相同；版本前缀没有记录，低版本哈希被当成高版本接受；超长密码在进入哈希前没有上限，一次请求把内存打满。verifier_rehash_plan.py 的 VerifierRehashPlan 要在登录成功路径上做惰性升级：识别多种哈希格式和参数，低于目标参数才重算，胡椒按版本逐个尝试并在成功后用当前版本重写，损坏记录转人工重置而不是中断批次，未知用户走固定耗时的假验证，重哈希按用户加锁且幂等，密码长度先做上限，结果带当前参数、目标参数和待升级数量。仓库里十五条用例现在全是红的。

