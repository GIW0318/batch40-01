# GSB Bugfix Task
## 题面
公会工资连错两周之后，两个大公会的会长分别把成员明细整理成表发给了运营。同一场团队活动被两个插件各上报一次，贡献加了双份；周结算踩的是自然周，和公会自己设的重置点差了十二个小时；成员拿贡献换合剂，余额没减，同一档能反复换；退会再入会贡献清零，工资记录却还在，等于领了两份；官员补发没有金额上限，操作几次就能把公会资金写成负数；贡献按在线时长自动增长，挂一晚上也能拿满；结算那一刻仓库材料不足，工资仍然照发；跨周补发落到了错误的周期，成员收到两份；贡献榜并列时按入会时间排，新成员当场表示不服；两个人同时兑换同一份贡献，两边都成功；后台查询会把未脱敏的内部账目一起带出来。guild_contribution_ledger.py 的 GuildContributionLedger 里 accrue、settle、redeem、ledger 各自维护账目。希望贡献事件按活动编号幂等，结算周期由公会配置决定，兑换先扣余额再发货，退会保留历史但失去领取资格，补发有上限且需要审批，结算前校验资金，查询返回快照，发货按流水号幂等并能识别重复邮件，工资明细记到人并标明资金来源，迟到上报进入下一期而不改写已结算账本，账本按公会和周期分区，补发与正常结算分开记账。test_guild_contribution_ledger.py 那十五个用例目前一条都过不去。

## 运行方式
```bash
python -m pytest tests -q
```
