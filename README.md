# GSB Bugfix Task
## 题面
审计日志上线防篡改链之后，法务抽查发现中间少了两天的记录，校验却全绿。链的摘要只取了上一条记录的载荷哈希，没有把上一条的链值算进去，删掉一条再补一条就能续上；序号有缺口时校验证直接跳过，没有报错；每日锚点只是写进另一个表，从来没有和链尾比对，历史被整体重写也看不出来；包含证明用错了根，拿别的批次也能验过；两个写入进程各自持有链尾，同时追加时链分叉，后写的分支被覆盖；记录按墙上时钟排序，时钟回拨后顺序和序号不一致；末尾记录被删除时没有后续记录引用它，谁都发现不了；序列化格式升级后旧记录重算摘要对不上，校验器直接跳过旧段；批量导入的锚点没有按序号排序；快照接口把整条链和盐值一起返回。audit_hash_chain.py 的 AuditHashChain 要把链值定义为包含前链值和规范化记录内容的摘要，序号连续且缺口报错，每日锚点必须和链尾一致并支持离线复核，包含证明绑定批次根，写入串行化或带冲突检测，按序号而不是时钟排序，尾部删除通过锚点和长度发现，序列化版本参与摘要并保留旧版本校验，快照只给摘要和长度。仓库里十五条用例现在全是红的。

