# GSB Bugfix Task
## 题面
战斗音效一密集，抢音就把爆炸声拦腰砍断。抢占只看谁先启动，不看优先级和距离，重要语音经常被脚边的环境音挤掉。被抢的 voice 直接停止，释放包络没走完，耳机里啪一声。混响和延迟的尾音跟着 voice 一起销毁，上一发炮弹的余响瞬间没了。被虚拟化的 voice 恢复时从头播放，连射的节奏全乱。同优先级的 voice 按哈希顺序抢，每次结果都不一样。最大发声数按通道算而不是按 voice，立体声一下占两个名额。抢占之后 bus 的通道计数没有减，越打越静，最后整组哑掉。语音播报和界面音效放在同一个池子里，被环境音轻松挤走。多线程同时申请 voice 时会超发，实际发声数超过上限。释放时没做去咔哒处理，密集场景一直响。循环音效被抢占后重新触发，淡入淡出参数没有恢复，接缝处音量突跳。长时间运行后 voice 句柄的代际号回绕，误杀刚申请的新 voice。抢音策略得综合考虑优先级、距离和剩余时长、被抢 voice 能保留效果尾音、虚拟化恢复能接上原时间轴、同优先级结果可复现、句柄代际不会误伤。15 条用例现在全数挂红。

## 运行方式
```bash
python -m pytest tests -q
```
