# GSB Bugfix Task
## 题面
安全审计给运维跳板机开了个高危：扫描器借自研 SOCKS5 网关打通了内网，认证形同虚设。我复现时发现，问题从握手第一步就开始了。配置了用户名密码，客户端说不支持认证，服务端仍按无认证继续；握手数据分两次到达，代码只读一次，后半段被当成请求；域名长度字段为零或超过 255 也接受；IPv6 地址带方括号时解析失败，合法请求反而被拒；上游还没连上就先回了成功应答，客户端以为已经通了；UDP 关联不校验来源地址，谁都能借它发 UDP；绑定请求被当成连接请求处理，监听端口开在错误地址；保留字节不是零也照常解析；认证版本号对不上时直接跳过认证；域名在本地解析，绕过了远端 DNS 策略；同一连接上并发握手和转发，状态互相覆盖；所有失败都回成功应答码，客户端无从判断。socks5_gateway.py 的 Socks5Gateway 要严格按双方都支持的方法选择认证，读取要能处理分包，域名长度和总长度都要校验，IPv6 字面量正确解析，上游连接成功后才回应答，UDP 关联校验来源并限制目标，绑定和连接走不同状态分支，保留字节必须为零，认证版本必须匹配，域名交给远端解析，每条连接维护独立状态机，转发阶段限制空闲时间和总字节数，认证失败要区分可重试和永久拒绝，应答码和真实结果一致。模块里那十五个断言现在全是红的。
