# GSB Bugfix Task
## 题面
边界代理自己解析 TLS 记录做审计，碰上大证书和分片记录就崩，业务握手也偶发失败。一条记录分两次 TCP 到达，代码只处理第一次读到的部分；一次读到三条记录，只解析了第一条，后两条直接丢；记录长度超过协议上限也接受，按声明分配大缓冲；握手消息跨多条记录，代码把每条记录当成完整消息；TLS 1.3 握手中间出现变更密码规格记录，也被接受；关闭通知之后又收到应用数据，仍然交给上层；握手没完成就收到应用数据，也照常解密；记录版本号和协商版本不一致，没有告警；空记录连续出现，解析循环空转；大量变更密码规格记录把 CPU 打满，没有数量限制；解密失败和应当丢弃的记录没有区分，连接被误杀；缓冲区压缩时把半条记录截断，下一次解析从中间开始。tls_record_assembler.py 的 TlsRecordAssembler 要增量缓冲并支持一次读多条记录，长度先校验再分配，握手消息跨记录重组，变更密码规格按协商版本决定接受与否，关闭通知之后的数据拒绝，握手顺序严格检查，版本不一致要告警，空记录要有上限，变更密码规格做洪泛限制，解密失败分类处理，缓冲区压缩不能破坏半条记录，缓冲区状态要能跨多次读取保持，记录层错误要有明确分类和计数，输出审计元数据。仓库里那十五个用例现在全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
