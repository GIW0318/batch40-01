# GSB Bugfix Task
## 题面
战场结算最近被玩家拿截图追着问。持续伤害在目标倒下后还会跳两下，击杀算给了最后跳伤害的术士，补刀的刺客什么都没有；同一帧里两个人同时打死目标，双方都弹出击杀提示，荣誉也发了两份；猎人宠物咬死的人，击杀只记在宠物名下，主人荣誉为零；助攻窗口写死八秒，目标复活后旧助攻还能再算一次；过量治疗被算成有效治疗，奶妈荣誉高得离谱；战斗结束时还没结算的击杀直接消失，玩家出战场才看到荣誉少一截；同一个击杀包因为重传被处理两次，荣誉累加；挂机被系统踢出的角色仍分到胜利方荣誉；查询接口把内部列表直接返回，前端改一下就能影响下一次结算。战场中途换人进来，补位玩家打出的伤害被算到被替换的人头上；战斗结束后的荣誉邮件把同一笔奖励拆成两封，玩家以为发了双份。battleground_credit_ledger.py 里的 BattlegroundCreditLedger 负责 record_damage、record_kill、assist、settle 和 standings。规则要求伤害只按实际扣血计，过量部分单独记；同一事件序号只结算一次；补刀者拿击杀，助攻按有效伤害和有效治疗在窗口内判定，复活要清掉旧助攻；宠物伤害归主人；结算后榜单不可再变，重复 settle 不重复发；离场和踢出按离场时刻截断。荣誉按事件时间统一排序，邮件合并成一封；换人要切断前一名玩家的伤害归属；结算记录要能按玩家和事件双向查询，客服复核时不用重跑整场。tests/test_battleground_credit_ledger.py 的十五条检查目前全红。

## 运行方式
```bash
python -m pytest tests -q
```
