# GSB Bugfix Task
## 题面
协作编辑的长连接网关加了帧审计，恶意客户端用分片和压缩把检查绕过去，还拖垮了几个房间。分片消息中间插入 ping，已经收下的分片被清空；控制帧载荷超过 125 字节也接受；控制帧被分片，代码按普通消息拼接；客户端帧没掩码也放行，服务端帧反而加了掩码；文本帧里的非法 UTF-8 直接透传；关闭帧里写了 1005 和 1006 这种不能上线的码；压缩上下文接管后重置窗口没同步，解压直接出错；最大消息长度按单帧算，一万个小分片轻松绕过；保留位没协商扩展也被置位，仍然继续解析；没有起始帧的继续帧被当成新消息；关闭握手不等对端回关闭帧，直接断 TCP；64 位长度最高位为一被当成合法长度。ws_frame_audit.py 的 WsFrameAudit 要支持分片和控制帧交错，控制帧不能分片且载荷有上限，客户端到服务端必须掩码、反方向不能掩码，文本帧做完整 UTF-8 校验，关闭码按规范拒绝保留值，压缩上下文和窗口同步，消息总长度而不是单帧长度受限，保留位必须已协商，继续帧必须有起始帧，关闭要完成双向握手，64 位长度最高位必须为零，解析要能增量喂数据并输出审计记录，审计记录要包含连接标识、帧类型、长度和判定结果。测试目录里的十五个用例当前均未通过。

## 运行方式
```bash
python -m pytest tests -q
```
