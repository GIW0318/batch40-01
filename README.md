# GSB Bugfix Task
## 题面
公司用 SCIM 把人事系统的入离职同步到二十几个 SaaS，上个月离职员工的账号还能登录三个系统。查下来停用用户只改了主记录，他所在的项目组还保留着成员关系，应用按组授权就把人放进来了；组内成员移除用带条件的补丁路径，实现不支持过滤条件，整条补丁被静默跳过；分页从零开始还是从一开始两边理解不同，同步循环要么漏掉最后一页，要么第一页重复；版本标识没有参与更新，两个人同时改同一用户，后提交的把先提交的覆盖；外部编号不唯一，同一个人被建了两个账号；嵌套组的成员变更没有往上层传播；删除接口返回成功，但用户的令牌和会话没清；用户名只是大小写不同就被当成新用户；批量接口里部分失败也返回整体成功；过滤器属性名大小写敏感，按邮箱查不到就当成新用户创建。scim_deprovision_sync.py 的 ScimDeprovisionSync 要保证停用和删除是幂等的，并且沿着组、角色、会话、令牌一路传播，分页游标稳定，版本冲突拒绝而不是覆盖，外部编号全局唯一，批量结果逐条返回，过滤器属性归一，删除后再次同步不能复活账号。仓库里那十五条用例一条也过不了。

## 运行方式
```bash
python -m pytest tests -q
```
