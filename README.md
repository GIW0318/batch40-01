# GSB Bugfix Task
## 题面
维护结束后的第一晚，三个固定团的团长先后找到运营，说进度号全乱了。甲团打了第一个首领，乙团的界面也显示已锁定；普通难度打完切英雄，队伍被挡在门外，两种难度共用了一份冷却；团长点了延长，到期时间没变，第二天维护后照样解锁；首领倒地那一秒有人掉线，重连进来进度里没有这个首领；灭团被记成击杀，团长拿着战斗记录来申诉；两个团几乎同时推倒同一个首领，双方的进度里都写了这一笔；从别的团转进来的人把原团进度一起带了过来，新团凭空少打一个；重置边界按本地时区切，跨时区的成员有人提前有人延后；已经锁定的首领还能再摸一次尸体并拾取；后台查询返回的集合能被直接改掉；角色删掉重建，旧锁定仍挂在账号上。raid_lockout_ledger.py 的 RaidLockoutLedger 管进入、记击杀、延长、重置和查询。进度号要按团本、难度、周期三者唯一；击杀只在死亡事件确认后写入，灭团和重置不算；延长只对未过期进度生效并顺延到下一周期末尾；重置统一按服务器周期边界；同一首领重复上报要去重；转入转出放在一个事务里，不能留下半份进度；查询返回副本。锁定详情要带每个首领的击杀时间和来源团；同账号不同角色的锁定互不影响；维护重启后从持久记录恢复；延长另写一条审计。tests/test_raid_lockout_ledger.py 那十五项，眼下没有一项能过。

## 运行方式
```bash
python -m pytest tests -q
```
