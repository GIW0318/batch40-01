# GSB Bugfix Task
## 题面
新副本上线后，排队和进本问题集中爆发。两个队伍同时申请最后一个空位，系统把同一个实例发给了双方，进去后互相看见对方；队伍解散后实例一直不回收，几天下来配额被占满；玩家掉线重连被分到新实例，原本打掉的 Boss 又活了；实例编号回绕后撞上旧实例，客户端直接读到别人的进度；排队超时的请求还占着坑，后面的人一直排不进；切难度后沿用旧实例，英雄本里刷出普通怪；队长换人后归属校验失败，全队被踢出；最后一人退出后的回收宽限期内，实例又被分配出去；容量查询读缓存，界面显示可进实际已满；跨服队伍成员被分到不同实例，进了本互相找不到；强制关闭实例时没通知客户端，全队卡蓝条。instance_registry_broker.py 的 InstanceRegistryBroker 负责 acquire、release、reconnect、heartbeat 和 capacity。分配要以队伍为单位原子占位，同一队伍只能有一个活动实例；掉线重连按队伍和实例双键找回，宽限期内保留状态；回收必须等心跳过期且没有在线成员；编号复用要跳过仍被引用的旧实例；容量以实时计数为准；关闭前先广播再回收。acquire 和 reconnect 都要校验队伍成员名单，名单变化后旧实例只能由原队长移交；实例回收要先落持久化标记再释放资源，进程重启后按标记继续回收；容量统计把排队中和已分配分开返回；心跳超时和主动释放走同一个回收入口。tests/test_instance_registry_broker.py 的十五项检查现在都没过。

```bash
python -m pytest tests -q
```
