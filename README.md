# GSB Bugfix Task
## 题面
边缘路由器接了一条新上游，一条更具体的路由把整片办公网流量带到了错误线路，业务大面积超时。路由起源授权里写的最大前缀长度没有看，只按前缀本身匹配，更具体的条目被放行；源头自治域和授权记录对不上时只写日志，路由照样装表；路径里自己的号出现两次，环路检测只查了相邻一跳；会话抖动后最大前缀计数清零，一次泄漏能灌进几十万条；抖动抑制时间写死，合法线路恢复后半小时不回切；前缀过滤器放行了默认路由，上游一抖全网跟着抖；带黑洞社区属性的路由没有按约定丢弃，流量继续被转发；下一跳不可达的路由仍然进入转发表；外部与内部邻居优先级配反，内部条目压过外部；撤销消息没把条目从路由表删掉，控制面和数据面不一致；路径里出现集合写法，起源校验直接跳过；四字节自治域的点分写法没解析，合法邻居被当成格式错误。bgp_prefix_guard.py 的 BgpPrefixGuard 要同时校验授权前缀和最大长度，起源不合法必须按策略拒绝而不是记日志，环路检测看完整路径，最大前缀计数跨会话保留，抖动抑制带可配置的恢复曲线，默认路由默认拒绝，黑洞社区按约定处理，下一跳不可达不进转发表，外部邻居优先于内部，撤销必须同步清理路由表和转发表，集合写法有明确处理规则，点分写法能解析，最终给出每条路由的判定理由。测试目录里躺着十五项，我按顺序过了一遍，每项都卡住。
