# GSB Bugfix Task
## 题面
自研的 QUIC 接入网关上周开始灰度，视频会议房间在弱网下体验很差，运维看板上的重传率一直下不来。抓包看客户端只是晚到了一点，服务端就把包判成丢失，重传包和原包前后脚到达，同一条流被重复写；丢包检测用的是固定两百毫秒定时器，没有按往返时延和探测超时来算，跨洋链路几乎每轮都误判；只带确认帧的包也被算进在途字节，拥塞窗口一直涨不上去；收到确认以后退避没有清零，下一次超时被拉得特别长；地址还没验证完就放开发送量，放大倍数超过协议允许的三倍；连接迁移到新路径后还沿用旧路径的拥塞状态，一上来就按旧带宽猛发；流结束的 FIN 在重传时丢了，接收端一直等不到收尾，房间关不掉；发送节奏没有令牌桶，确认一到就整窗突发，交换机端口排队抖动；密钥更新期间的 1-RTT 包被当成未知包丢掉，画面黑一秒；发送线程和确认线程同时改统计，运维看到的在途包数和实际对不上。quic_loss_recovery.py 里的 QuicLossTracker 现在要能维护已发数据包的账本，按包数阈值和时间阈值判定丢失，探测超时要指数退避并在有效确认后复位，地址验证前严格限制发送量，连接迁移要按路径分开拥塞状态，发送要受节奏预算约束，流重传必须保留偏移和结束标志，统计快照要能并发安全地读。仓库里那十五条用例现在一条都过不了。
