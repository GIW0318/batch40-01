# GSB Bugfix Task
## 题面
合作方给我们发签名清单，我们用他们的规范化和签名库验签，上周发现两份内容不同的清单都能验过。问题出在规范化：重复键一个取第一个一个取最后一个，签名和验签各拿各的；数字 1.0、1 和 1e0 被写成不同字节，双方各自序列化后对不上；字符串里的非 ASCII 字符一边输出原字符一边输出转义，签名范围就不一样；键的排序按本地化规则而不是码点，同一个对象排出两种顺序；NaN 和无穷大被序列化成文本照签；控制字符的转义写法不统一；签名端和验签端各自跑了一遍规范化，版本号不同，输出的字节就不一样，版本号本身又没有进入签名范围；密钥编号没有和签名绑定，攻击者换一把自己的密钥再改编号也能过；分离签名的编码带不带填充两种都收；空值和缺失字段被当成一样。canonical_sig_verify.py 的 CanonicalSigVerify 要提供唯一的规范化字节流：重复键拒绝，数字按统一格式输出且拒绝非有限值，字符串统一转义规则，键按码点排序，规范化版本号参与签名且双方必须一致，验签针对签名时记录的规范化摘要而不是重建对象，密钥编号必须来自可信密钥集并参与签名范围，分离签名编码严格校验，空值和缺失分开处理。仓库里十五条用例眼下全部报错。

