# GSB Bugfix Task
## 题面
先看 fw_shadow_analyzer.py 里的 RuleShadowAnalyzer。安全团队拿它跑了一遍现网规则，报告和人工复核对不上，几条真正被遮住的拒绝规则反而没报出来。我把差异逐条摊开，问题集中在这些地方。最前面的允许任意来源规则把后面一条拒绝完全盖住，工具只标了内容重复；端口区间 1000 到 2000 覆盖 1500 到 1600，工具按字符串比较，没识别出包含关系；网段用字符串前缀判断，10.1 被当成包含 10.10.0.0/16；协议写 tcp 和写数字 6 被当成两条不同规则，实际完全等价；源地址取反的规则没有建模，工具报了一堆误报；有状态放行和后面的显式规则混在一起，新建连接和已建立连接没有分开看；默认拒绝策略没有参与分析，最后那条兜底规则被忽略；两条规则只是部分重叠，工具要么全判遮蔽要么完全不报；每次运行输出顺序都不一样，同一个规则集生成两份不同报告；ICMP 的类型和代码没进匹配条件，回显请求和不可达被当成同一类；NAT 转换前后的规则顺序没有建模，转换后的地址和规则对不上；注释不同但内容相同的规则没有合并，报告里全是噪声。它要先把协议、端口区间和地址段统一表示，再做包含、部分重叠和等价判断，正确建模取反条件，把有状态规则和新建连接规则分开，默认策略必须参与，输出顺序稳定可复现，ICMP 类型代码单独匹配，标明规则处在 NAT 前还是 NAT 后，等价规则去重，最后按完全遮蔽、部分遮蔽、冗余和关联四类给出机器可读的理由。仓库自带的十五条断言目前全挂。

