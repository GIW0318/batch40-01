# GSB Bugfix Task
## 题面
后台上了风险自适应认证之后，安全运营发现高敏感操作反而更好绕：修改收款账户只要求密码登录，风险分再高也不触发二次验证；宽限期从第一次敏感操作开始算，之后一直续，用户连续操作两小时都不再验；风险信号只在登录时算一次，中途换了城市、换了设备也没人管；风险服务超时的时候，代码走的是放行分支。二次验证凭证没有绑定具体动作，验完一次就能拿去删库；验证方式还能降级，要求硬件密钥的场景传短信码也收；用户可以在低保障会话里把自己的新设备标成可信；两个高敏感请求并发进来，都在等验证，结果两个都执行了；决策缓存只按用户编号做键，换一个资源还命中旧结论；审计只记了通过，没记绕过和降级。stepup_decision_gate.py 的 StepupDecisionGate 要在每次敏感动作前重新算风险，宽限期按动作单独计时且不可滑动续期，风险服务不可用时按拒绝处理，验证凭证绑定用户、动作和资源且一次性使用，验证方式只能升级不能降级，可信设备登记要求足够的保障级别，并发请求串行化，决策结果带命中规则和有效期。仓库里那十五条用例目前没有一条通过。

## 运行方式

```bash
python -m pytest tests -q
```
