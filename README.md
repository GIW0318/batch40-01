# GSB Bugfix Task
## 题面
多租户网关把 HTTP/2 连接复用后，一个慢租户就能把整条连接堵死，其他租户的请求排队到超时。抓包和指标里能看到：单个流把连接窗口吃满后不再归还；权重相同的流没有轮转，先到的流一直优先；优先级树里依赖已关闭的流仍然占位置；RST_STREAM 之后窗口没有释放；最大并发流数按连接算而不是按租户算；连接级窗口更新被延迟到批量发送；慢客户端不读响应时服务端继续缓存；CONTINUATION 帧没有计入头部大小；GOAWAY 发出后仍接受新流；填充字节算进了流控但没算进配额；公平调度只按流数量不按字节；队列里同一个租户的流可以无限增长。h2_flow_fairness.py 的 FlowFairness 负责 admit、on_window、schedule、reset 和 stats，窗口、优先级和租户配额现在各存一份。要求窗口按流和连接分别归还，优先级树清理关闭流，RST 释放额度，租户级并发和字节配额同时生效，慢客户端触发背压，CONTINUATION 和填充计入头部预算，GOAWAY 后拒绝新流，调度按字节和流数双维度公平。test_h2_flow_fairness.py 的十五条用例当前全部失败，覆盖窗口归还、权重轮转、依赖清理、RST 释放、租户并发、批量更新、慢客户端、CONTINUATION、GOAWAY、填充、字节公平和队列上限。

## 运行方式
```bash
python -m pytest tests -q
```
