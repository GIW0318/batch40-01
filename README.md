# GSB Bugfix Task
## 题面
设备接入平台换 MQTT broker 以后，指令重复下发，离线消息丢了一批，主题权限也串了。服务质量二级的释放消息重发两次，订阅端收到两条相同指令；清理会话标志为假时，会话存在标志给错，客户端以为旧会话还在；用空载荷清除保留消息，结果被当普通消息丢掉，旧状态一直留着；客户端正常断开也发了遗嘱消息，告警天天误报；主题权限的通配符把系统主题也匹配进去，普通设备能读系统消息；在途消息窗口超过上限仍继续投递，设备内存被打满；报文标识在上一条没确认前被复用，响应错配；两个订阅主题重叠，同一条消息投递两次；保活超过一点五倍没有断开，僵尸连接占着会话；不同服务质量的消息乱序到达，状态更新被旧指令覆盖；broker 重启后遗嘱消息没恢复，设备掉线没人知道；主题别名映射按连接共享，两个客户端互相串别名。mqtt_session_broker.py 的 MqttSessionBroker 要保证二级服务质量只投递一次，正确给出会话存在标志，空载荷清除保留消息，遗嘱只在异常断开时发送，主题权限排除系统主题，在途窗口严格执行，报文标识未确认不得复用，重叠订阅去重，保活超时强制断开，同一主题保持顺序，遗嘱持久化，主题别名按连接隔离，会话存储能在重启后恢复。这批十五条用例眼下全部是失败的。

