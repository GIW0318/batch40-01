# GSB Bugfix Task
## 题面
监控大屏上跳出一条告警：同一个外部端口被两个内部主机同时使用。出口 NAT 网关刚扩到四台，内部访问外部服务开始随机串会话，值班同学一度以为是监控标签配错了。并发分配端口时两个流拿到同一个外部端口，回包被送到错误的内网机器；端口在 TIME_WAIT 结束前被复用，旧连接的迟到包污染新连接；UDP 和 TCP 用同一套超时，DNS 流刚建就过期，长 UDP 会话又永远不释放；收到 ICMP 不可达时按五元组找不到绑定，错误没法回注给内网；内部主机访问同网段的公网映射地址，流量绕不回来；只有第一个分片能解析出端口，其余分片直接被丢弃；表满时淘汰最老的绑定，不管它是否还在活跃；清理任务每次全表扫描，流量一大就卡住转发线程；回程方向没有把源目地址和端口对调，回包匹配不上；绑定快照在并发更新时读到一半新一半旧；IPv6 前缀转换后长度变化，反向拼不回原地址；同一个内部五元组在绑定过期前重复申请，拿到两个外部端口。NatBindingTable 在 nat_binding_table.py 里，得把端口分配做成原子操作，记录 TIME_WAIT 状态避免提前复用，TCP 和 UDP 分别设置超时，ICMP 错误按内层五元组回查，支持内部访问映射地址的发夹路径，分片先缓存再按首片重组，表满时按空闲时间而不是创建时间淘汰，清理改成增量扫描，回程严格反转元组，快照要一致，IPv6 前缀映射必须可逆，同一内部元组重复申请返回原绑定。这十五条用例现在全是红的。
