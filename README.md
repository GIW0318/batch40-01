# GSB Bugfix Task
## 题面
我们把群体角色的蒙皮搬到 GPU 以后，战场上经常看到角色抽一下或者整条手臂接到腿上。骨骼脏标记只标了自身，子骨骼没跟着更新，抬手时小臂停在上一帧。骨骼调色板是双缓冲的，GPU 还没消费完下一帧就覆盖上去，快速镜头下人物会闪一下旧姿势。根运动的位移在调色板和对象变换里各应用一次，角色跑起来像在冰上滑。骨骼数超过二百五十六以后索引高位回绕，手指矩阵串到脊椎上。导入时整体缩放过模型，绑定姿势的逆矩阵没有重算，所有角色小了一圈。实例化蒙皮网格共用同一个调色板基址，同屏十个守卫做出一模一样的动作。异步计算写调色板和图形队列读取之间没有屏障，偶尔整片花屏。每帧把整块调色板上传，带宽超预算，低端机直接掉到二十帧。骨骼被删掉后材质还引用旧索引，读到的是垃圾矩阵。暂停菜单开着的时候仍然每帧重传，白耗电。双相机渲染时第二个相机拿到的是下一帧的调色板，分屏两边动作差一帧。这边的要求是脏标记能沿层级传递、双缓冲有明确的在途保护、骨骼上限和实例基址不再串、上传量能按实际脏骨骼裁剪。这 15 条用例眼下全部挂着红，没有侥幸过的。

## 运行方式
```bash
python -m pytest tests -q
```
