# GSB Bugfix Task
## 题面
金币和绑钻的兑换所上线后，经济组发现有人靠报价漏洞套利。报价缓存过期了还能成交，玩家拿着十分钟前的低价一路换；手续费逐笔四舍五入再加总，和整批一次算的结果对不上，差额越滚越大；两个请求同时兑换，同一个余额被扣了两次，账户变成负数；兑换失败只回滚了一边货币，另一边已经到账；每日限额按请求次数算，拆成一百笔小额就能绕过；同一个幂等键重复提交，生成两笔成交；管理员改汇率时，已经锁定的订单被重新计价；先换过去再换回来，扣完手续费反而多出金币；余额查询读到扣款和入账之间的中间态；维护窗口内的请求没有被拒绝，落在半开状态。报价接口对同一请求连续返回两个汇率，客户端取到哪个全看网络重试。exchange_quote_book.py 的 ExchangeQuoteBook 负责 quote、execute、cancel、limits 和 balances。报价要有有效期和版本，执行时按锁定版本结算；手续费按总额一次计算，余数归属写清楚；扣款和入账在同一事务，任一失败全回滚；限额按币种和金额累计；幂等键全局唯一；改价不能影响已锁订单；维护期直接拒绝。同一版本的报价在缓存期内必须返回同一结果；兑换流水要记录报价版本、成交价和手续费明细；批量兑换和单笔兑换共用同一套限额与舍入规则。tests/test_exchange_quote_book.py 的十五条用例现在全红。

## 运行方式
```bash
python -m pytest tests -q
```
