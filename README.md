# GSB Bugfix Task
## 题面
容器运行时把基础镜像的 seccomp 配置和应用自带的白名单合并后，几个本该被拦的系统调用放行了：合并时默认动作取了应用的允许，基础配置里的拒绝整段丢失；同一个系统调用一边允许一边返回错误码，实现按字母序取了后面那个；不同架构的系统调用编号没有归一，六十四位和三十二位配置互相覆盖；参数过滤的比较运算符在合并时被归一成相等，原来的大于等于条件失效；按架构分的段落被平铺成一张表，后面的段把前面的覆盖；同一系统调用重复出现时后者生效，审计看不到冲突；白名单里的未知系统调用被静默忽略；通知类动作被当成允许；包含和注释的解析把整段配置读成一行；配置里的架构名写成别名，x86_64 和 amd64 被当成两套规则，实际只生效一套。seccomp_profile_merge.py 的 SeccompProfileMerge 要先解析成按架构分组的规则集，再做交集式合并：默认动作取更严格的一方，同名系统调用的动作按严格程度合并，参数过滤逐项比较且保留原比较语义，未知项和通知动作明确报错或标记，架构段独立保存，重复项记录冲突，架构别名先归一。仓库里的十五条用例眼下全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
