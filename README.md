# GSB Bugfix Task
## 题面
多租户 SaaS 网关按 SNI 选证书，最近接了一批客户自定义域名，证书错配的投诉一直不断。通配符证书把 a.b.example.com 也匹配上了，可它只应该覆盖一层标签；域名末尾带点、大小写混写、中文写法和 punycode 写法被当成四个不同的名字，同一张证书在四套表里各存一份；客户端不带 SNI 时，服务端随手拿第一张证书顶上，而不是租户配置的默认证书；客户端明确只支持 HTTP/1.1，服务端仍然选了 h2，连接刚建立就被重置；在 A 域名签出的会话票据，拿到 B 域名复用时也被接受；证书热更新不是原子的，一半 worker 用新证书一半用旧证书，握手随机失败；SNI 里夹了空字节或者非法 UTF-8 也照常进入路由，日志被截断；同名证书配了两份，选中哪份取决于哈希表遍历顺序，每次重启结果都不一样；证书有效期只检查了生效时间，已经过期的证书还在对外服务；热更新后 OCSP 装订还是旧的，客户端吊销检查失败；热更新和握手并发时会读到半张证书链，直接报内部错误；通配符匹配跨了多个标签层级。sni_cert_router.py 的 SniCertRouter 要先把域名归一成小写、去掉末尾点、统一成 A-label，再按精确名和单层通配匹配，没有 SNI 时使用显式默认证书，ALPN 取双方交集，票据必须和签发时的域名绑定，证书加载要整批原子切换并带版本号，非法 SNI 直接拒绝，有效期两端都要检查，装订响应随证书一起更新，选择和热更新都要能被并发安全地读取。自带的十五条 pytest 跑下来没有一条通过。

## 运行方式
```bash
python -m pytest tests -q
```
