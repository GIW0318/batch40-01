# GSB Bugfix Task
## 题面
多租户构建集群换成 cgroup v2 之后，一个租户的构建把整台机器拖死：内存上限设得比当前用量还低，写入成功但内核一直回收不掉，任务卡在不可中断状态；内存高水位设得比硬上限还大，限流永远不触发；交换分区上限写零却被解析成不限制；子组的内存上限超过父组，父组先被撑爆；进程数上限写 max 被当成零，所有任务起不来；CPU 配额的周期和配额单位搞反，配额大于周期，等于不限；委派子组时只改了目录属主，没有放开控制器，子组根本建不出来；统计接口递归累加，父组数字把子组算了两遍；组名里带斜杠，创建时跑到了别的层级；修改上限不是原子操作，一半生效一半失败也不回滚。cgroup_limit_guard.py 的 CgroupLimitGuard 要在写入前做整棵树的约束检查：硬上限不得低于当前用量，高水位不得高于硬上限，交换上限独立生效，子组不得超过父组，进程数上限区分 max 和数字，CPU 配额和周期校验范围，委派要同时检查属主和控制器，组名只允许安全字符，统计按直接子组聚合，批量修改失败要回滚并给出原因。仓库里十五条用例现在全部报错。

## 运行方式
```bash
python -m pytest tests -q
```
