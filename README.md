# GSB Bugfix Task
## 题面
发布包的哈希每次构建都不一样，查了半个月发现构建输入清单根本没管全：子模块只记了顶层提交，子模块里的提交换了也没人发现；工具链写的是版本范围，构建机装到哪个小版本全看运气；环境变量没有白名单，代理地址和临时目录把构建结果带偏了；打包时把当前时间写进归档，同样的源码两次构建哈希必然不同；调试信息里带绝对路径，换一个工作目录就变；文件遍历顺序取自文件系统，同一批文件打成两种顺序；语言区域和时区没有固定，排序和日期格式跟着机器走；生成文件只在构建后出现，清单里没有它们的输入来源；符号链接和普通文件没有区分，解引用后内容变了；基础镜像只写了标签没写摘要，标签一漂移整条链就换了；构建参数的顺序变化被当成不同输入。build_input_manifest.py 的 BuildInputManifest 要把一次构建的全部输入固定下来：源码和子模块精确到提交，工具链精确到版本和校验值，环境变量按白名单记录，时间戳、路径前缀、文件顺序、区域和时区都归一，生成文件要能追溯到生成步骤，符号链接保留链接语义，基础镜像固定到摘要，参数按名称排序。仓库里十五条用例现在全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
