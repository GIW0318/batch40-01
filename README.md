# GSB Bugfix Task
## 题面
红队报告里有一句话：重叠分片可以让边界检测和终端看到两份不同的内容。我们拿报告里的样本复现，正常的大包反而被误丢。重叠分片后到的数据覆盖先到的，检测看到的和终端看到的不是同一份内容；首片很小，后续片偏移指向首片内部，代码直接拼接；偏移乘以 8 之后溢出，算出负的缓冲位置；重复分片按长度累加，总长度超过首片声明值；重组超时设成五分钟，攻击者用大量半包占满内存；各片长度之和不等于首片声明值，仍然交付；IPv6 分片头的下一头部没解析，内层协议认错；原子分片被当成普通分片缓存；单个数据报的分片数量没有上限；不分片位置位却收到分片，没有按冲突处理；收到的需要分片消息没有回给上层，路径发现失效；每个源地址的重组队列没有配额，一个源就能把表打满。IpFragmentReassembler 在 ip_fragment_reassembly.py 里，需要固定重叠取舍策略并保持检测与终端一致，偏移和长度先做边界校验，乘法溢出要拦住，重复分片按区间去重，超时和内存都有上限，总长度必须自洽，IPv6 下一头部正确解析，原子分片直接放行，分片数量设上限，不分片冲突有明确结果，需要分片消息回注上层，按源做配额和淘汰，超时淘汰不能误伤刚开始到达的队列，重组结果要带完整性标记和分片统计。tests 目录下那十五项检查眼下都没有通过。

## 运行方式
```bash
python -m pytest tests -q
```
