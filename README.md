# GSB Bugfix Task
## 题面
开放世界开跑车的时候，路边贴图一会儿糊成色块，一会儿又黑一帧。流式加载的请求按提交顺序排队，不是按可见性和距离，远处山顶的高清贴图会抢在近处路面之前占 IO。同一张纹理的几级 mip 被重复标记在途，队列里出现好几份相同请求。显存吃紧时淘汰算法挑中了正在采样的纹理，画面闪黑一帧才恢复。预算按压缩后的大小算，解压驻留之后实际占用远超显存。IO 完成顺序和请求顺序不一致，低级别 mip 后到却覆盖了已经上传的高清层。异步回调回来时流式句柄已经被释放，回调往悬空对象写，偶尔崩在加载线程。反馈缓冲一溢出就把最热的 tile 丢掉，近景来回重载，硬盘灯常亮。碎片整理搬动正在被 GPU 采样的块，地面出现花屏。纹理数组层数增加后驻留表没有扩容，新层永远停在最低 mip。主线程每帧同步等 IO 完成，进新区域必卡一下。平台最大纹理尺寸不同，超限的那张整张降级成纯色，也没人报警。我们要的是请求按可见性排序、同一纹理不重复在途、淘汰避开在用资源、预算按驻留后大小核算、回调生命周期安全，加载不能阻塞主线程。15 条用例现在全是失败状态，清一色红。

## 运行方式
```bash
python -m pytest tests -q
```
