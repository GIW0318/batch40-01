# GSB Bugfix Task
## 题面
云存档改成多端同步后，玩家开始互相覆盖进度。两台设备最后修改时间一模一样，后上传的直接盖掉先上传的；离线设备时间被调到未来，永远赢，正常进度反而被覆盖；合并之后任务进度倒退，已经交过的任务又回到可接；冲突时生成两份存档，界面只显示一份，另一份永远选不到；上传中断留下半份文件，下次同步直接报损坏；校验和只算正文不算元数据，改过时间戳也能过；玩家删了存档，云端同步又把它恢复回来；跨版本合并把新字段清空，装备强化等级归零；同账号两个角色的存档串号，战士读到法师的背包；自动同步和手动上传并发，最后落盘的是旧数据；回滚到旧版本后，新版本存档被旧格式覆盖。cloudsave_conflict_merge.py 的 CloudsaveConflictMerge 要处理 upload、download、merge 和 resolve。冲突判定用版本向量而不是单时间戳；服务端时间作为兜底；合并按字段级规则，进度取并集但完成状态不可回退；半份上传进临时区，校验通过才切换；删除用墓碑记录，防止复活；跨版本先迁移再合并；同账号角色按角色编号隔离。会话冲突要先确定唯一写入者，另一个会话进入只读；只读会话的修改另存为冲突稿；上传和下载都要带存档版本和角色编号；同一存档槽只允许一个活动上传。tests/test_cloudsave_conflict_merge.py 的十五条断言当前全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
