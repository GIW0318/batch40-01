# GSB Bugfix Task
## 题面
Helpdesk 这周收了二十多张单，都是 VPN 改版后访问内网慢、域名解析到公网、断线时流量裸奔。我跟着装了两台机器，问题比工单描述的还多。排除列表里的网段仍被更具体的包含路由送进隧道；内网域名走了物理网卡的 DNS，解析到公网地址；只装了 IPv4 路由，IPv6 流量从物理网卡直接出去；网卡切换时断网保护有几百毫秒的放行窗口；按应用分流只看进程路径，程序改名就绕过规则；DHCP 下发的路由度量更小，压过 VPN 路由；重连后旧路由没清，流量走已经断掉的隧道；包含和排除规则重叠时优先级没有定义，结果全看顺序；分离 DNS 的应答缓存没按接口区分，内网答案被外网查询复用；访问本地打印机也被送进隧道，局域网发现失败；策略热更新先删旧规则再装新规则，中间有空窗；IPv4 映射的 IPv6 地址绕过 IPv4 排除规则。SplitTunnelPolicy 落在 split_tunnel_policy.py，得按最长前缀匹配并明确包含与排除的优先级，DNS 按接口分别解析和缓存，IPv6 路由和排除规则同步生成，断网保护失败时关闭而不是放行，应用身份按签名而不是路径判断，路由度量以策略为准，重连先清理旧路由，重叠规则有确定结果，本地网段显式放行，策略切换原子完成，映射地址归一后再匹配，策略版本和生效时间要能查询，最后能导出实际生效的路由和 DNS 快照。这十五条用例现在全部报错。
