# GSB Bugfix Task
## 题面
上周把网关的令牌校验从每次回源查询改成进程内缓存之后，登出基本失效了：用户点了退出，手里那个访问令牌还能继续调接口，直到自然过期；运营封了一个账号，它在缓存里的令牌照样放行。更麻烦的是我们按用户维度缓存，结果把一个人的一台设备踢下线，他另外两台设备也跟着掉线；有台设备先被撤销、后来又重新登录，旧令牌和新令牌共用一个缓存键，新令牌反而被当成已撤销。凌晨做批量吊销时，吊销事件比缓存里的旧结果晚到，后写的旧快照把新状态盖了回去；两个网关实例的时钟差了两分钟，一边认为令牌已过期，另一边还在放行。令牌编号没有按签发方区分，不同环境生成的同号令牌互相能过。缓存也没有上限，被扫描器用随机令牌打了几十万个空结果，进程内存一直涨；快照接口还把内部的撤销集合直接返回给调用方。token_revocation_cache.py 里的 TokenRevocationCache 现在要同时管准入、吊销和失效传播，按签发方加令牌编号建立索引，支持按账号批量吊销但只影响吊销时刻之前签发的令牌，负缓存要能被后续吊销事件覆盖，时间一律用调用方给的时刻，跨实例的吊销要能合并。仓库里那十五条用例目前没有一条通过。

## 运行方式

```bash
python -m pytest tests -q
```
