# GSB Bugfix Task
## 题面
证书装订检查上线后，运维发现网关对中间证书的吊销状态几乎没有判断力，几张已经作废的证书一直能握手。must-staple 的叶子证书没带票据也放行；票据的有效期起点在将来、终点已过去都按有效处理；签名者不是签发机构，也没有授权代表链；请求里的随机数没有回显校验；状态写着已吊销却只打一条告警；票据和叶子证书的绑定字段对不上；所有错误都被软失败策略放过；缓存键只用了叶子证书，换签发机构仍命中旧票据；并发抓取时旧结果覆盖新结果；票据体超长仍继续解析；证书链上只有第一张被检查。ocsp_staple_gate.py 的 StapleGate 负责 verify、fetch、cache、policy 和 snapshot，票据、缓存和策略现在各存一份。必须做到：must-staple 缺失直接拒绝；有效期按允许偏差判断；签名者和授权代表逐级确认；随机数必须匹配；已吊销立即失败；票据与叶子证书绑定；软失败只对网络故障生效；缓存键带完整链；并发抓取按版本取新；票据体有上限；链上每张证书分别检查。tests/test_ocsp_staple_gate.py 的十五条检查眼下全部失败，覆盖缺票据、有效期两端、签名者、随机数、吊销、绑定字段、软失败、缓存键、并发覆盖、体积上限和多证书链。

## 运行方式
```bash
python -m pytest tests -q
```
