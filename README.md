# GSB Bugfix Task
## 题面
竞技场投降和掉线判负最近争议很大。双方同时点投降，系统结算了两次，双方都记负；掉线超过宽限判负，但玩家重连后仍然站在场内继续打；投降投票已经通过，战斗还在继续；三对三里一个人掉线，队伍立刻判负，另外两人没有等到翻盘；认输的一方照样拿到赛季点数；比赛结束后再发投降请求，居然能把结果改成胜；平局时按投降次数决定胜负，先点的吃亏；重赛申请和结果写入并发，同一场出现两条记录；投降冷却没生效，有人连续投降刷低分匹配；观战回放显示的胜负和结算面板相反。投降投票里掉线成员的票被算成反对，四打五永远投不过；比赛记录里的结束原因写成投降，实际是掉线。pvp_forfeit_arbiter.py 的 PvpForfeitArbiter 负责 vote_forfeit、disconnect、reconnect、finalize 和 record。投降要按队伍计票，达到阈值才通过；掉线先进入宽限状态，宽限内重连恢复，超时才判负；finalize 只能成功一次，之后所有操作返回已结束；结果写入和重赛申请串行化；投降冷却按账号和场次记录；回放结果从同一份结算记录读取。掉线成员在投票中按弃权处理，不计入分母；结束原因由最后一个有效事件决定；同一场次的投票、掉线、重赛共用一份事件序号。tests/test_pvp_forfeit_arbiter.py 的十五个用例目前全部失败。

## 运行方式
```bash
python -m pytest tests -q
```
