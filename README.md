# GSB Bugfix Task
## 题面
服务网格改成双向 TLS 之后，几个内部服务开始互相认错身份：证书主体只取了通用名，两个部门都有人叫 ops 的证书互相能调；主体备用名里的 URI 做了百分号解码后又比较，编码不同但语义相同的两个名字被当成不同主体；通配符证书里的星号跨了两级子域也匹配上了；证书链只验了叶子，自签的中间证书塞进请求头也能过；证书过期后连接不断，映射缓存里还留着旧身份。证书吊销只在握手时查一次，长连接挂一天也不再看；根证书轮换时新旧两套并存，实现只加载了旧的，新签发的证书全部被拒；带未知关键扩展的证书被当成普通证书接受；主体名大小写和结尾的点不归一，同一个服务出现两个身份；代理转发来的客户端证书头，任何来源都能伪造。mtls_principal_map.py 的 MtlsPrincipalMap 要按完整证书链和策略建立主体，优先使用 URI 备用名，通配符只允许最左一段且不能跨标签，吊销状态按连接生命周期复检，根证书支持多套并存并在轮换期同时信任，未知关键扩展拒绝，转发头只在可信代理来源下采信，映射结果带证书指纹和有效期。仓库里的十五条用例当前全部报错。

## 运行方式
```bash
python -m pytest tests -q
```
