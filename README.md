# GSB Bugfix Task
## 题面
我们那个开放世界换季版本上线后，材质系统就开始出洋相。美术在同一份母材质上勾了雾、雪、湿滑几组关键字，结果每勾一次就多编译一份，缓存命中率几乎为零；同样是雾加雪，关键字顺序一换哈希就对不上。异步编译的回调回来时材质实例已经切到别的变体，句柄写错，角色身上直接变成粉色占位。磁盘缓存只按关键字算版本，显卡驱动升级后旧二进制照读，进游戏就花屏甚至驱动重置。预热队列没有帧预算，进关卡第一帧把几百个变体全塞进去，主线程卡了快一秒。缓存淘汰更离谱，正在编译的变体被 LRU 扫掉，回调往已经释放的槽位写。还有母材质改了默认关键字，子实例的覆写没有失效，雪地里人物还在用晴天的光照分支。特化常量不同取值的两个变体被合成一个，阴影强度和颜色全错。多线程同时 miss 同一个变体时会各自编译一遍，最后互相覆盖。变体数量到上限之后直接静默丢弃，远景建筑随机退回默认材质。编辑器里热重载 shader 源码，磁盘缓存也不失效，改完看着像没生效。我们要的是关键字集合与特化常量能稳定归一、并发 miss 只编译一次、缓存版本能识别引擎和驱动变化、预热有明确帧预算且回调不会写到失效槽位；缺失变体要有可查的降级记录，而不是一片粉色。仓库里那 15 条用例现在一条都过不了，全是红的。

## 运行方式
```bash
python -m pytest tests -q
```
