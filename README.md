# GSB Bugfix Task
## 题面
上周做双机热备演练，切换脚本执行完，数据库连接全断，长连接业务集中报错。备机的状态表和主机对不上，值班同学只能先回切。只同步新建连接，切换时已建立连接在备机根本查不到；握手过程中的连接没有同步，切换后收到确认不知道属于哪条流；序列号转换差一个窗口，切换后大量报文被当成乱序；非对称路由时回包走另一台，状态查不到直接丢弃；同步消息乱序到达，旧状态覆盖新状态；两台机器的超时配置不同，备机提前清掉活跃连接；切回主机后同一连接出现两份状态，计数翻倍；同步链路断了没有全量重建，两边静默分叉；地址转换和连接跟踪分开同步，转换后的地址对不上；TCP 窗口缩放因子没带过去，窗口算错；关联的 ICMP 连接没有建立关系，错误报文被丢；备机状态表满时直接淘汰，没有按优先级保留。ConntrackSyncAgent 在 conntrack_failover_sync.py 里，得支持全量和增量同步，覆盖握手中和已建立状态，序列号差值要能还原，非对称路由能按反向元组查表，更新带版本号防止旧覆盖新，超时参数两端一致，切回时去重，同步恢复后全量校准，地址转换和连接跟踪作为整体同步，窗口缩放因子随状态走，ICMP 关联关系要建立，容量不足按优先级淘汰，最后能输出两端状态差异。仓库随附的十五条断言现在全部失败。
