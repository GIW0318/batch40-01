# GSB Bugfix Task
## 题面
一个第三方应用在接入后第三天被安全团队下了线，原因是它拿到的权限比申请的多。排查发现刷新那一步没有重新求交，签发时展开的读写层级在刷新时又把父权限带了回来，应用顺带拿到了当初没勾的写权限；未知权限被静默丢掉，应用以为申请成功，调用时才碰壁；令牌没有绑定受众，给报表服务签的那份能直接调结算接口；权限字符串的空格和大小写不同就算两项，审计表里同一项被拆成两行；代客操作时代理人声明没有校验，普通账号可以冒充另一个用户；用户把授权范围改小，已经发出去的令牌仍按旧范围生效；空权限列表被当成全部权限；权限别名在同意页和实际签发之间对不上；单个令牌能塞的权限数量没有上限，超长的值把请求头顶爆。scope_attenuation_plan.py 的 ScopeAttenuationPlan 把权限当成集合做衰减：刷新和委托只能取签发时那份的子集，未知权限明确报错，受众必须显式限制，代客场景核对代理人链路，范围变更让旧令牌失效，别名先展开再比较，空集合不等于全集，结果给出有效权限、被裁掉的部分和拒绝原因。这套东西配了十五项检查，从上周到现在就没绿过。

```bash
python -m pytest tests -q
```
