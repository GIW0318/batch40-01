# GSB Bugfix Task
## 题面
新 HDR 管线接上 bloom 之后，夜景里所有霓虹边缘都像蒙了一层灰。亮度阈值是在 sRGB 空间算的，线性空间里的高光根本没被提取出来，路灯芯子不发光，反倒是灰色墙面被当成亮部。降采样遇到奇数尺寸时最后一行一列直接丢掉，光斑边缘偏了半个像素，动起来还会抖。场景里偶尔有一个 NaN 像素，经过几级模糊扩散成整屏白，得切场景才恢复。上采样相加时把原图又加了一遍，亮部过曝，暗部也跟着泛白。窗口分辨率一改，mip 链尺寸没重建，画面被横向拉长。曝光是在 bloom 之后才应用的，结果暗部也参与发光，夜里像起了大雾。半分辨率缓冲没有做像素中心对齐，亮斑拖尾方向总是偏一点。每帧都新建临时渲染目标，带宽和显存都超预算，低端机掉帧明显。时间性降噪的缓存没在相机剪切时清理，快速转头会留下上一帧的光斑残影。bloom 强度设成零仍然跑完整条链路，纯属白烧。主视图和 UI 相机共用同一个输出目标，界面文字也跟着发光。这套链路要在正确的色彩空间提取亮部、奇数尺寸不丢边、异常值不扩散、分辨率切换能完整重建，整条后处理的开销也要算进帧预算。这 15 条用例目前集体失败，全红，没有一条能站住。

