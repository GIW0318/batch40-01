# GSB Bugfix Task
## 题面
装备方案切换上线后，玩家开始丢装备。背包满的时候切方案，换下来的旧装备没地方放，直接消失；两个方案引用了同一件饰品，切到另一个方案后第一个方案里变成空位；切换过程中角色被控制或者死亡，状态停在半套装备上；双手武器和副手同时被方案选中，系统没有拦住；套装加成按切换前的装备计算，换完面板还是旧属性；两个切换请求并发，属性加成叠了两份；切换失败只回滚了武器，防具留在新方案里；战斗中也能随意切换，没有冷却；装备绑定后仍能通过方案跨角色使用；方案里存了已删除的物品编号，整次切换直接失败；属性面板缓存没刷新，聊天里报的数值和实际不符。loadout_swap_guard.py 的 LoadoutSwapGuard 要处理 save、apply、preview 和 revert。切换要先预占背包格，放不下就整体拒绝；每个物品同时只能被一个方案占用；切换在一个事务里完成，失败全回滚；双手武器与副手互斥；套装和属性在切换完成后统一重算；战斗状态和冷却由调用方传入并校验；已删除物品在预览阶段就报出来。快捷栏和技能绑定要跟着方案一起换；预占背包格按方案差集计算，不能按整包复制；切换期间角色进入短暂锁定，其他装备操作排队；方案保存时校验物品归属和唯一性。tests/test_loadout_swap_guard.py 的十五个用例目前全红。

## 运行方式
```bash
python -m pytest tests -q
```
