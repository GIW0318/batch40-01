# GSB Bugfix Task
## 题面
海外同事反馈，客户端切到加密 DNS 以后，首次解析特别慢，内网域名干脆解析不了，证书告警也多了起来。我抓了几次包，发现问题从引导解析就开始了。引导解析还是走系统 DNS，加密 DNS 服务器自己的域名先被污染；证书固定只比叶子证书，换了中间 CA 以后全部失败；响应内容类型是网页也拿去解析，报错信息完全看不懂；协议要求消息编号为零，客户端发了随机编号，服务端直接拒绝；查询没有填充，长度泄露了用户访问的域名；HTTP/2 返回错误方向码后还在同一条连接上重试，一直被拒；缓存键没区分 DNSSEC 和检查禁用位，两类结果互相污染；响应被截断时没有重试，直接返回半截记录；回退到明文 UDP 时没有提示，查询内容裸奔；多个并发查询复用同一个 HTTP/2 流，响应错配；返回的 TTL 没有上限，缓存时间过长；域名不存在和服务故障映射成同一个错误码。doh_resolver_client.py 的 DohResolverClient 要用固定地址引导并校验服务器身份，证书固定到公钥而不是叶子，检查内容类型，消息编号固定为零，查询按块填充，遇到方向错误码换连接重试，缓存键包含 DNSSEC 和检查禁用位，截断响应走 TCP 或重发，回退策略显式且默认不降级明文，一次查询一条流，TTL 设上限，响应码逐一对映，引导结果要能缓存但不能永久固定，回退切换要有明确日志和计数。这十五条用例目前全是失败状态。
