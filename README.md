# GSB Bugfix Task
## 题面
流量审计的回放系统重新做 TCP 重组，告警里常见的关键字被拆成两半，真正的攻击流量反而漏了。两段数据重叠时，有时先到的赢有时后到的赢，同一个抓包文件跑两遍结果不同；序列号从三十二位最大值回绕，排序把后面的段当成很早以前的数据；重传段长度不一样，同一段数据被算了两遍；乱序段到达时直接丢掉，缺口一直等不到就永远不吐数据；中间缺一个段，整条流卡住，后面几十兆都不处理；FIN 占一个序列号没算进去，下一条流的数据整体错位一个字节；带紧急指针的数据被当普通数据处理，边界和优先级都错；每条流的缓冲没有上限，几个大流就把内存吃光；两个方向的流合并到同一个缓冲，请求和响应混在一起；VLAN 双层标签时 TCP 头偏移算错，端口读成乱码；IP 分片没有先重组，非首片被当成完整 TCP 段；抓包时间戳回跳，淘汰逻辑把新数据先清掉。pcap_stream_reassembly.py 的 TcpStreamRebuilder 要固定重叠数据的取舍策略并写进结果，序列号比较要能跨回绕，重传按区间去重，乱序段先缓冲，缺口超时后给出明确标记而不是无限等，FIN 要消耗序列号，紧急指针单独处理，每条流和全局都有内存上限，两个方向分开维护，正确跳过 VLAN 和 QinQ 头，先做 IP 分片重组，淘汰按单调时间，输出要可复现。这十五条用例目前全部报错。

```bash
python -m pytest tests -q
```
